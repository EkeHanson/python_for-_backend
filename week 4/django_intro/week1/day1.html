What is Django?

Django is a Python framework that makes it easier to create web sites using Python.

Key Features:
  • Batteries-included: Comes with ready-to-use features like login system, database connection, and CRUD operations
  • DRY (Don't Repeat Yourself): Emphasizes reusability of components
  • Database-driven: Especially helpful for database driven websites
  • Secure: Built-in protection against common security threats
Django History: Invented by Lawrence Journal-World in 2003 to meet short deadlines in the newspaper industry. Initial release to the public was in July 2005. Latest version is 5.1.7.
Why Django for APIs? Django REST Framework (DRF) extends Django to build powerful, flexible APIs with minimal code. We'll use DRF exclusively — no templates!
How Does Django Work? (MVT)

Django follows the MVT design pattern (Model - View - Template).

Model The data (database)
→
View Request handler
→
Template Response layout (HTML)

Model

The model provides data from the database. Django uses ORM (Object Relational Mapping) to make it easier to work with databases without complex SQL.

# models.py
class Member(models.Model):
  firstname = models.CharField(max_length=255)

View

A view takes http requests, imports models, finds what data to send, and returns the final result.

# views.py
def members(request):
  return HttpResponse("Hello world!")

Template

A template describes how the result should be represented (HTML with Django tags).

<!-- template.html -->
<h1>My Homepage</h1>
<p>My name is {{ firstname }}.</p>
Note for DRF: In this course, we will use Django REST Framework which replaces templates with serializers and returns JSON responses instead of HTML.
Django Request Flow

When a browser requests a URL, this is what happens:

1. Browser requests URL → urls.py matches the URL pattern
2. views.py receives the request and calls the matching view
3. View imports relevant models from models.py
4. View sends data to a template (or serializer for DRF)
5. Template returns finished HTML/JSON back to the browser
Key Files in a Django Project:
  • urls.py — URL routing
  • views.py — Request handlers
  • models.py — Database tables
  • settings.py — Project configuration

Create Virtual Environment

It's suggested to have a dedicated virtual environment for each Django project.

What is a virtual environment? An isolated Python environment that keeps project dependencies separate from other projects.

Create a virtual environment using venv (included in Python):

$ python -m venv myworld

This creates a folder named "myworld" with subfolders and files.

Activate the virtual environment:

Windows

$ myworld\Scripts\activate.bat
(myworld) C:\Users\Your Name>

Unix/MacOS

$ source myworld/bin/activate
(myworld) ... $
Note: You must activate the virtual environment every time you work on your project.
Install Django

Now that we have created a virtual environment, we are ready to install Django.

Important: Remember to install Django while you are in the virtual environment!

Django is installed using pip:

(myworld) $ python -m pip install Django

Create Django Project

Navigate to where you want to store your project (in the virtual environment) and run:

(myworld) $ django-admin startproject my_tennis_club

Django creates a folder with this structure:

my_tennis_club/
   manage.py
   my_tennis_club/
      __init__.py
      asgi.py
      settings.py
      urls.py

Key Files:
  • manage.py: Command-line utility for Django
  • settings.py: Project configuration
  • urls.py: URL routing

Create Django App

An app is a web application with specific meaning in your project (like a members database).

Create an app named "members":

(myworld) $ python manage.py startapp members

Django creates a folder with this structure:

members/
   migrations/
      __init__.py
   __init__.py
   admin.py
   apps.py
   models.py
   tests.py
   views.py
Key Files:
  • models.py: Database tables
  • views.py: Request handlers
  • admin.py: Admin interface configuration
  • migrations/: Database change history
Note: You cannot have a web page created with Django without an app.
Views & URLs

Views are Python functions that take http requests and return http responses.

Open members/views.py and add:

from django.shortcuts import render
from django.http import HttpResponse

def members(request):
    return HttpResponse("Hello world!")

Create members/urls.py:

from django.urls import path
from . import views

urlpatterns = [
    path('members/', views.members, name='members'),
]

Update root my_tennis_club/urls.py:

from django.contrib import admin
from django.urls import include, path

urlpatterns = [
    path('', include('members.urls')),
    path('admin/', admin.site.urls),
]
Visit: http://127.0.0.1:8000/members/ to see "Hello world!"
Models & Migrations

A Django model is a table in your database.

Create a Member model in members/models.py:

from django.db import models

class Member(models.Model):
    firstname = models.CharField(max_length=255)
    lastname = models.CharField(max_length=255)

Create migration file:

(myworld) $ python manage.py makemigrations members
Migrations for 'members': members\migrations\0001_initial.py - Create model Member

Apply the migration to create the table:

(myworld) $ python manage.py migrate
Applying members.0001_initial... OK
SQLite Database: Django creates db.sqlite3 in your project root. All models become tables in this database.
View SQL: python manage.py sqlmigrate members 0001 shows the SQL statement that was executed.
